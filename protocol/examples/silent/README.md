# SILENT Experiments

This crate contains the SILENT paper experiment runners.  In the standalone
artifact, commands should be run from the repository root that contains the
top-level `Cargo.toml`.

Common entry points:

```bash
cargo run --manifest-path Cargo.toml -p silent --bin silent_reproduce -- --mode smoke
protocol/examples/silent/scripts/run_silent_experiments.sh 5 smoke
```

The one-command script runs SILENT's own artifact experiments only. It does not
run baseline or comparison-system experiments. Generated CSV/Markdown outputs
go under `target/silent-experiments/` unless `OUT_DIR=...` is set.

## Paper-to-Artifact Map

Use this map when checking paper terminology against the repository:

- Typed transitions / `Share2HE` / `D2S-Refresh`: the paper-specific reproducer
  is `protocol/examples/silent/src/bin/silent_reproduce.rs`, function
  `bench_hss_mul`, which emits the CSV case
  `hss,share2he_d2s_hss_mul_slots_*`.  The reusable operator path is
  `protocol/crates/silent-operators/src/hss_slots.rs`, where
  `HssSlotEngine::mul_slots` calls the share-to-HE and HE-to-share conversion
  routines before returning additive shares.  The underlying threshold/HSS share
  operations are in `core/crates/silent-hss/src/ops.rs`, with key
  splitting in `core/crates/silent-hss/src/keygen.rs`.
- `D2S-Refresh` availability barriers: the generated parameter manifest emits
  `protocol_model,bert_base_refresh_barriers` from
  `protocol/examples/silent/src/bin/silent_params_report.rs`.
- Share-domain transport and masked conversion reproducers: the q-share to
  p-share masked-opening helper is
  `protocol/crates/silent-operators/src/conversion.rs`, the linear
  bridge state is `protocol/crates/silent-operators/src/linear_bridge.rs`,
  and the TCP-loopback reproducer is exercised by
  `protocol/examples/silent/src/bin/silent_bert_base_runner.rs` through
  the `q_to_p_bridge_values_98304_tcp_loopback` row.
- Appendix C parameter audit: see
  `protocol/examples/silent/appendix_c/README.md`.  The default
  reproduction script writes the parameter manifest, BERT-shaped RPM-CNIM block
  audit, OF-PMPE no-wrap audit, and optional randomized-digest audit to
  `target/silent-experiments/`; the stricter complete RPM-CNIM parameter audit
  is generated by
  `protocol/examples/silent/scripts/make_rpm_parameter_audit.py` only when
  the caller supplies the matching projected-error bounds and external
  RLWE-estimator output.
- Parameter-set labels: reusable presets such as `current-bfv-v1` and
  `current-hss-v1` are defined in
  `core/crates/silent-params/src/presets/current.rs` and surfaced in
  the SILENT artifact by `silent_params_report`.

## Evidence Policy

The artifact deliberately separates paper-facing evidence from engineering
probes.  A row should be cited in the paper only when its scope matches the
claim being made.  In particular:

- `silent_cmatmul_suite` reports BERT-shaped RPM-CNIM block geometry, byte
  counts, timings, and correctness checks.  Its current packed-linear maps use
  `noise_bound=0`, so these rows must not be used as a query-hiding or
  parameter-security certificate.
- `make_rpm_query_hiding_audit.py` reports only randomized-digest
  multi-query LHL entropy margins for candidate parameters.  Its rows carry
  `paper_usable=false` until the matching projected-error bound and RLWE
  estimator audit pass for the same parameter file.
- `make_rpm_parameter_audit.py` combines randomized-digest entropy,
  projected-error slack, and externally supplied RLWE estimator bits.  It does
  not run a lattice estimator and does not infer mask/error bounds.  Rows stay
  `paper_usable=false` unless all conditions pass and the caller explicitly
  supplies `--allow-paper-usable`.
- `make_wan_sensitivity.py` is an analytic WAN model from measured bytes and
  public availability-flight counts.  It is useful for sensitivity discussion,
  but it is not a Linux `tc` or real-cloud deployment measurement.
- `run_glue_task_fidelity.py` is a conservative downstream-task fidelity probe.
  Its output is marked `paper_usable=false` by default because the current path
  approximates the public neural template and still needs verification against
  the final fixed-point protocol semantics before any accuracy claim is made.
- `collect_gelu_activation_stats.py` records BERT intermediate-dense activation
  statistics for choosing public GeLU approximation ranges.  It is a diagnostic
  range-calibration tool, not a protocol benchmark.

## Review-Response Scripts

Run the standard smoke reproduction:

```bash
protocol/examples/silent/scripts/run_silent_experiments.sh smoke
```

Generate the optional RPM-CNIM entropy-only query-hiding audit when candidate
mask parameters are available:

```bash
SILENT_RUN_RPM_QUERY_AUDIT=1 \
SILENT_RPM_KAPPA_2048=2 \
SILENT_RPM_KAPPA_4096=2 \
SILENT_RPM_MASK_HINF_2048=54 \
SILENT_RPM_MASK_HINF_4096=109 \
protocol/examples/silent/scripts/run_silent_experiments.sh smoke
```

The entropy audit is intentionally not enabled by default, because the numbers
are meaningful only when copied from the same parameter file used for the
projected-error and RLWE-estimator checks.

Generate a stricter candidate RPM-CNIM parameter audit when the projected-error
bounds and external estimator output are available:

```bash
python3 protocol/examples/silent/scripts/make_rpm_parameter_audit.py \
  --log2-q-2048 54 --log2-q-4096 109 \
  --kappa-2048 2 --kappa-4096 2 \
  --mask-min-entropy-per-coeff-2048 54 \
  --mask-min-entropy-per-coeff-4096 109 \
  --eta0-linf-2048 1 --eta1-linf-2048 1 \
  --eta0-linf-4096 1 --eta1-linf-4096 1 \
  --mask-coeff-linf-bound-2048 1 \
  --mask-coeff-linf-bound-4096 1 \
  --rlwe-classical-bits-2048 128 \
  --rlwe-classical-bits-4096 128 \
  --estimator-status-2048 screen-pass \
  --estimator-status-4096 screen-pass
```

The example above demonstrates CSV shape only.  Do not cite it unless every
bound is copied from the audited deployment parameter file and the estimator
rows are attached.

Run the GLUE fidelity probe only after installing optional Python dependencies
or providing local GLUE TSV files:

```bash
python3 protocol/examples/silent/scripts/run_glue_task_fidelity.py --task sst2 --split validation \
  --approx-gelu --gelu-template global_deg6 --gelu-clip-bound 3.0
```

If a row reports degraded task accuracy, low label agreement, or remains marked
`paper_usable=false`, do not cite it as evidence in the manuscript.  The
`paper_usable_reason` field is part of the result, not a comment.

Collect GeLU pre-activation statistics for range debugging:

```bash
python3 protocol/examples/silent/scripts/collect_gelu_activation_stats.py \
  --task sst2 --split validation \
  --output target/silent-experiments/silent_gelu_activation_stats_sst2_validation.csv
```

Current GLUE diagnostics show that the original `global_deg6` template is not
task-fidelity ready.  A degree-12 refit over `[-3,4]` improves SST-2 validation
substantially (`0.9243 -> 0.9209`, label agreement `0.9920`), but MRPC
validation remains poor (`0.8775 -> 0.8603`, label agreement `0.9142`) and QNLI
label agreement is still below the acceptance threshold.  Treat these rows as
guidance for future coefficient design, not as paper evidence.
