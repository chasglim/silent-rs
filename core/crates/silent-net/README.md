# 异步广域网多方安全计算（MPC）通信基座设计文档

项目背景：面向低延迟隐私神经网络推理（Low-Latency Private Neural Network Inference for WAN-Restricted Cloud Services）的底层架构设计。

## **1. 动机 (Motivation)**

在广域网（WAN）受限的云服务环境下，底层网络通信是制约 MPC 性能表现的核心瓶颈。现有的开源 MPC 框架多基于局域网（LAN）的同步假设，导致在真实生产环境下表现欠佳，主要痛点包括：

- **TCP 队头阻塞 (Head-of-Line Blocking)**：传统基于 TCP 的同步/半同步模型在面临网络丢包或延迟抖动时，会导致整个计算流停滞。
- **HSS 计算特性的错位**：同态秘密共享（HSS）后端通常将神经网络映射为受限乘法直线（RMS）形式。这种模式下，各节点的本地计算进度是天然异步的，强制的同步屏障（Barrier）极大浪费了 CPU 算力。
- **协议与传输耦合**：多数库将协议逻辑与 Socket 绑定，难以适应复杂的混合协议（如 HSS 份额分发与高频微小 Secret Sharing 数据包混杂）需求。

## **2. 目标 (Goals)**

- **极致抗抖动能力**：在跨地域部署时，实现不同算子/流之间的通信互不干扰，最大化掩盖 WAN 延迟。
- **通信与算子解耦**：实现“完全通信序列化”，底层传输层（TCP/QUIC/Memory）对上层密码学协议完全透明。
- **Rust 原生异步生态**：深度集成 `tokio` 运行时，利用 Rust 的所有权模型确保高并发下的内存安全与零成本抽象。
- **多路复用支持**：能够同时高效支撑 HSS 的大块数据分发与 OT 扩展、三元组生成的碎片化交互。

##  **3. 核心架构设计 (Core Design)**

### **3.1 纯异步事件驱动与无锁调度**

系统废弃传统的“屏障对齐”同步模型。每个密码学算子（如非线性门转换、分布式解密）被抽象为一个独立的异步任务。当节点完成本地 RMS 块计算后，立即发出份额并继续推进后续子图，由 Rust 的 `Futures` 机制在数据到达时自动唤醒计算节点。

### **3.2 完全通信序列化 (Full Communication Serialization)**

所有跨节点消息必须通过序列化层处理：

- **元数据定义**：消息头包含 `TaskID`、`GateID` 和 `SessionID`。
- **序列化选型**：推荐使用 **FlatBuffers**（零拷贝特性）或 **Cap'n Proto**，以减少在高吞吐推理下的 CPU 序列化开销。

### **3.3 基于 QUIC 的多路复用传输层**

这是本设计的核心创新点。QUIC 基于 UDP，在应用层实现了可靠传输，并原生支持单连接内的多路复用。
在混合协议推理中，为不同的计算流（如 Transformer 的不同 Attention Head）分配独立的 QUIC Stream。即使某条 Stream 丢包，其他 Stream 的计算仍能并行推进，彻底解决 TCP 的阻塞问题。

### **3.4 动态后端适配器 (Transport Adapters)**

通过 Rust 的 `Trait` 定义统一的 `Transport` 接口，支持以下后端动态切换：

- **Memory Channel**：用于单机多进程模拟、算法验证及极速测试。
- **TCP + io_uring**：针对高性能局域网机房部署，追求最低的应用层开销。
- **QUIC (Quinn/Quiche)**：针对 WAN 环境的默认选项，提供最强的网络韧性。

## **4. 与现有方案对比 (Comparison)**

| 特性           | 传统方案 (如 MP-SPDZ)       | 新一代同步方案 (如 MOTION)         | 本设计方案 (异步+QUIC)            |
| -------------- | --------------------------- | ---------------------------------- | --------------------------------- |
| 网络模型       | 同步 / TCP                  | 半同步 / 通信序列化 (TCP)          | 纯异步 (Event-driven)             |
| WAN 延迟适应性 | 极差，受限于 TCP 握手与阻塞 | 一般，序列化有所改善但仍受制于 TCP | 极佳，QUIC 多路复用规避阻塞       |
| HSS 计算契合度 | 低，强制对齐导致算力闲置    | 中等，支持部分流解耦               | 完美，匹配 RMS 异步调度特性       |
| 安全性与并发   | C++ (手动管理内存)          | C++ (高度优化的线程池)             | Rust (强安全、Tokio 原生异步)     |
| 部署灵活性     | 固定 Socket 绑定            | 支持抽象消息接口                   | 可插件化 Transport (TCP/QUIC/Mem) |


## **5. 结论**

本设计方案通过 “完全通信序列化 + 异步 QUIC 传输 + 零成本抽象” 的组合，从工程底层解决了 HSS 协议在广域网落地的性能痛点。相比于现有库，它更专注于真实云服务环境下的低延迟表现，是构建高鲁棒性、高性能开源 MPC 库的理想通信基座。
